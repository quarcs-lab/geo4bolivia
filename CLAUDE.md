# Working with Claude on GDO-Bolivia

The GeoDevelopment Observatory of Bolivia: subnational development data for Bolivia across spatial scales, with the Python package `geo4bolivia`. This repository was created from the geo4cambodia template; see `TEMPLATE.md`.

## Read first

- `docs/data-infrastructure.md`: how the database works (scales, geo IDs, metadata, aggregation rules, loading with and without the package, building indicators)
- `CONTRIBUTING_DATA.md`: how to add a dataset or a scale
- `project.yaml`: project identity. Generic code reads the country, repository and package from it; never hard-code them

## Project structure

- `project.yaml`, `geo/scales.yaml`, `metadata/*.datapackage.json`, `raw/`: edited by hand
- `geo/units.*`, `geo/boundaries/`, `geo/crosswalks/`, `data/<scale>/`, `docs/datasets/`, the catalog CSV: generated by `geo4bolivia build`. Never edit them
- `src/geo4bolivia/`: the package
  - generic modules: `project`, `store`, `scales`, `metadata`, `io`, `create`, `bridge`, `aggregate`, `validate`, `cli`
  - `build/`: `common.py` and `gadm.py` are generic; `geo.py` and the dataset builders are project-specific
- `tests/test_core.py`: generic tests. `tests/test_project.py`: facts about this project's data

## Environment (uv)

```bash
uv sync                                 # dependencies + the package (editable)
uv run geo4bolivia build [geo|<dataset>]   # regenerate from raw/
uv run geo4bolivia validate                # must pass before committing
uv run pytest
```

- Always use `uv run`. Commit `uv.lock`; never commit `.venv/`.
- After changing `raw/`, `metadata/`, `geo/scales.yaml` or `src/geo4bolivia/build/`, run build, validate and pytest, and commit the regenerated files.

## Spatial scales and geo IDs

IDs nest by prefix: `BO` › `BO-NN` › `BO-NN-NN` (GADM order). Scales: department, province, municipality (see `geo/scales.yaml`). Codes from other sources are kept as columns of `geo/units.csv`, never used as keys.

## Loading data

```python
!pip install -q geo4bolivia       # Google Colab
import geo4bolivia as geo
geo.load("<dataset>", years=2020, geometry=True)
geo.link(my_table, scale="department", on="Name")      # names or codes -> geo_id
geo.zonal("raster.tif", scale="municipality", name="ntl")    # raster -> panel
geo.combine([...], scale="department")                   # datasets on one scale
df, df_def = geo.for_expdpy("<dataset>")                # for expdpy (pass variables as analysed, e.g. logs)
gdf, df, df_dict = geo.for_geometrics("<dataset>")      # for geometrics (pass levels; it logs internally)
```

Without the package: `https://raw.githubusercontent.com/quarcs-lab/geo4bolivia/main/<path>`.

Every Python snippet in the README and docs runs as-is in Google Colab: it starts with `!pip install -q ...` and is followed by the Open-in-Colab badge, linking to `https://colab.research.google.com/notebooks/empty.ipynb`.
